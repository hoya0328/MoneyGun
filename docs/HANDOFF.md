# MoneyGun 핸드오프

## 2026-09-03 — 김뉴스(NOVA) 공식 공시 감시

- `news_events`와 `news_poll_runs`를 추가했다. OpenDART 접수번호로 중복 제거하고 원문,
  종목, 수집/게시 시각, 분류 버전, 근거, 확인자를 보존하며 수집·확인을 감사 원장에 남긴다.
- `NOVA-DISCLOSURE-RISK-v1`은 공시 제목을 INFO/WARNING/CRITICAL로 결정론적으로
  분류한다. WARNING은 소유자 확인 전, CRITICAL은 확인 여부와 무관하게 발견 후 72시간
  해당 종목 신규 BUY를 차단한다. SELL·대사·킬 스위치는 차단하지 않는다.
- 평일 07:30~18:30 KST 5분 폴러와 Supervisor 생명주기를 추가했다. 자동 감시가 켜진
  환경에서는 최근 성공 폴링 없음·실패·15분 초과 시 BUY 생성과 제출을 모두 실패 폐쇄한다.
- 직원 사무실에 실제 뉴스룸을 추가했다. 출처/상태/건수/차단 공시/DART 원문/소유자
  확인을 제공하며, 일반 뉴스 공급자는 정식 계약 전까지 `NOT_CONFIGURED`로 표시한다.
- `Stop-DesktopLive.ps1`이 API·웹뿐 아니라 MoneyGun의 종가·멀티모드·뉴스 작업자도
  검증 후 종료하게 보강해 이전 작업자 고아 프로세스를 남기지 않는다.
- 집중 검증: 김뉴스 테스트 5개, Ruff, TypeScript, Vite 프로덕션 빌드, PowerShell 3개
  구문 검사가 통과했다. 서비스 종료 상태의 전체 회귀는 API 90/90, PowerShell 전체 구문,
  `pip check`, `npm audit`까지 통과했고 릴리스 후보 `d7bc5ca`로 고정했다.
- 이 구현과 검증은 실제 브로커 주문을 제출하지 않는다. OpenDART 이외의 일반 뉴스는
  아직 자동 분석하지 않는다. 새 커밋의 실거래 재활성화는 소유자 승인 전까지 차단한다.
- 로컬 재기동 후 OpenDART 8종목에서 26건을 수집했고 WARNING 2건을 신규 BUY 차단으로
  표시했다. 수집 전후 L0 실주문 의도는 1건으로 같았고 브로커 제출은 0건이다. 뉴스룸은
  데스크톱/390px 가로 넘침·이름 없는 버튼·브라우저 오류가 모두 0이며 현재 런타임은
  최종 소유자 승인과 키움 복구 대사 4/4 뒤 `ARMED`다. L0 대사·감사·복식원장은 PASS,
  기존 외부 보유종목 1개는 계속 제외되고 활성화 과정의 브로커 주문 제출은 0건이다.

## 2026-09-02 — 집중·장초·안전·장기 L0 공통 운용 경로

- `FOCUS-MOMENTUM-KR-v2-L0`, `OPEN-RANGE-KR-v3-L0`,
  `BALANCED-TREND-KR-v1-L0`, `LONG-TREND-KR-v1-L0`를 추가했다. 기존 OOS 전략과
  결과는 유지되며 새 전략은 모두 `PASS_L0_EXPERIMENTAL`로만 표시한다.
- 안전·장기 모드 프로필과 미션을 idempotent seed로 추가했다. 집중·안전·장기는
  15:35 완료 일봉 전시장 스캔→다음 장 09:05 공식 호가 주문안→L0 대사→승인 대기까지
  연결된다.
- 장초는 08:50 감시목록, 09:00~09:10 주문금지 실시간 수집, 09:10~10:30 현재
  1분봉 돌파 주문안까지 연결된다. 수집 상태는 SQLite에 보존되고 재접속 프레임은
  거래량을 부풀리지 않도록 보수적으로 중복 제거한다.
- 공통 청산 감시는 무효화, 최대 보유기간, 전략별 수익 고점 추적, 장초 11시 전량
  조건을 검사해 SELL 승인 대기를 만든다. 실제 MoneyGun BUY 체결 수량보다 많은 SELL은
  생성·제출 두 단계에서 차단되며 기존 외부 보유종목은 계속 제외한다.
- 운영센터에 5개 모드 상태, 집중/안전/장기 실행, 장초 실시간 실행, 청산 감시 버튼을
  추가했다. 멀티모드 스케줄러는 Supervisor에 연결했지만 새 릴리스 점검 전 기본값은 꺼짐이다.
- 검증: API 84개 통과·1개 실행 중 DESKTOP_LIVE 뮤텍스 테스트 제외, 신규 모드 테스트
  5개 통과, Ruff·TypeScript·프로덕션 웹 빌드·diff check 통과. 실제 주문 제출 0건.
- 남은 운영 단계: 현재 실행 중 API를 새 코드로 재기동하면 `RECOVERY_REQUIRED`가 된다.
  릴리스 점검, 복구 대사, 멀티모드 스케줄러 설정과 소유자 재승인 전에는 실제 자동 준비를
  활성화하지 않는다.

## 2026-09-02 — 5만 원 전시장 종가매매 v3-L0

- 키움 조회 전용 어댑터에 `ka10030` KOSPI·KOSDAQ 거래대금 순위 연속조회를 추가했다. 관리종목·우선주는 요청 단계에서 제외한다.
- `CLOSE-AUCTION-KR-v3-L0`가 15:05~15:10에 자격 보통주/시장조치 이력과 순위를 대조하고, 2,000~45,000원·시총 500억 이상·유동성/추세/과열 조건으로 최대 16종목을 상세 분석한다.
- DESKTOP_LIVE Supervisor에 릴리스 승인형 루프백 스케줄러를 연결했다. 15:20~15:27에는 최신 호가→L0 대사→그림자 주문→`AWAITING_APPROVAL`까지만 준비하며 자동 승인·자동 제출은 없다. 새 릴리스 재검사 전 설정 기본값은 꺼짐이다.
- 주문 화면에 전시장 대조 행, 1주 매수 가능 종목, 상세·소형주 분석 수, 후보/HOLD 근거와 수동 현재 단계 실행 버튼을 추가했다.
- 기존 브로커 보유종목은 MoneyGun LIVE 체결 계보에 없는 한 `unmanaged_broker_positions_ignored`로 유지된다.
- 이 변경 뒤 실제 브로커 제출을 재개하려면 전체 검증과 새 릴리스 점검을 거쳐야 한다. 코드 검증 결과는 이 절의 마지막에 갱신한다.
- 검증: API 79개 통과, 종가/키움 집중 테스트 10개 통과, Ruff·TypeScript·프로덕션 웹 빌드·`git diff --check` 통과. 데스크톱 뮤텍스 단독 테스트 1개는 실제 DESKTOP_LIVE API가 이미 잠금을 보유해 예상대로 두 번째 획득을 거부하므로 실행 중 환경에서는 제외했다.
- 초보자용 `docs/USER_GUIDE.md`를 추가해 시작·재기동 복구·화면별 역할·종가 시간표·5분 승인·주문 상태·긴급 중지·장 종료·문제 해결을 한 문서로 정리했다.
