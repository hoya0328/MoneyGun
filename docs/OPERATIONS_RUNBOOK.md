# MoneyGun 로컬 운영 런북

최종 갱신: 2026-08-31

## 현재 허용 범위

- 키움 운영계좌 조회, 공식 국내 일봉·호가·미체결·체결·잔고 대사
- OpenDART 공식 공시와 재무제표 수집
- R0 연구와, 승격 후 R1 공식 그림자 주문
- 로컬 알림, 감사·원장 검증, 백업과 격리 복구 훈련
- 실제 브로커 주문: **금지**. 주문 키·릴리스 승인·거래 플래그는 닫아 둔다.

## 매일 장 종료 후

웹 `운영 센터`에서 `오늘 업무 실행`을 누르거나 다음 명령을 15:40 KST 이후 한 번 실행한다.

```powershell
.venv\Scripts\python -m moneygun_api.operations_worker
```

정상 결과는 `COMPLETE / DAILY_CLOSE_COMPLETE`다. 같은 날짜 재실행은 같은 운영 런과 일일 롤업을 갱신하므로 운영일·결정 수를 중복 증가시키지 않는다. 주말과 장 종료 전에는 `SKIPPED`가 정상이다.

## 확인 순서

1. `그림자 운영 준비`와 7개 준비 카드가 모두 정상인지 본다.
2. OOS가 `실거래 차단`이면 주문 단계를 올리지 않는다.
3. 직원 보고함에서 `실제 주문 0건`을 확인한다.
4. 계좌 대사 또는 데이터 품질이 FAIL이면 원인을 고치기 전 재개하지 않는다.
5. 운영센터의 `안전 백업 만들기` 후 `복구 훈련`을 주 1회 실행한다.
6. 코드·환경 변경 후 `장애 대응 4종 훈련`을 실행한다.

## 자동 실행 등록 시 원칙

- Windows 작업 스케줄러에는 평일 15:50 KST에 위 명령만 등록한다.
- `--force`를 예약 작업에 사용하지 않는다.
- 작업 디렉터리는 저장소 루트로 고정하고 `.env`는 Git에 추가하지 않는다.
- 중복 스케줄러를 만들지 않는다. 일일 운영 런의 DB 멱등성은 최후 방어선이지 중복 운영 허가가 아니다.

## 백업과 복구

- 온라인 백업은 `data/backups/moneygun-<UTC>.sqlite3`에 새 파일로 생성한다.
- 체크섬과 `PRAGMA integrity_check`가 PASS인 백업만 정상으로 본다.
- 복구 훈련은 임시 디렉터리에서만 수행하며 운영 DB를 덮어쓰지 않는다.
- 실제 복원은 서비스 중지, 원본 보존, 대상 경로 확인과 별도 사용자 승인을 받은 뒤 수행한다.

## 현재 승격 차단 사유

- OOS 거래 93건으로 최소 100건 미만
- Sharpe 0.734로 0.8 미만
- DSR 0.9351로 95% 미만
- MDD -53.57%로 집중투자 게이트 -30% 초과
- OpenDART 과거 정정 전 값의 완전한 고정 미구현
- 현재 상장 종목 고정 목록의 생존편향 미제거

이 여섯 항목을 데이터나 코드를 조작해 우회하지 않는다. 다음 전략 버전 또는 시점 고정 데이터셋에서 사전 정의한 동일 게이트로 다시 검증한다.
