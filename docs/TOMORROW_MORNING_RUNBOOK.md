# MoneyGun 내일 아침 L0 실행 안내

기준일: 2026-09-02  
대상: 한국 주식 50,000원 L0 승인형 실거래 파일럿  
현재 판정: **소프트웨어 구현 완료 · 외부 운영 잠금 미완료로 실주문 차단**

## 오늘 밤 반드시 끝나야 하는 외부 설정

실제 비밀값은 채팅·문서·Git에 보내지 않고 로컬 `.env` 또는 운영 Secret Manager에만 입력한다.

1. 이미 발급받은 키움 **실전** App Key와 Secret을 격리된 주문 변수 `KIWOOM_ORDER_APP_KEY`, `KIWOOM_ORDER_SECRET_KEY`에도 명시적으로 연결한다. 키움은 별도 조회/주문 키를 발급하는 구조가 아니지만 MoneyGun은 프로세스 권한을 분리하기 위해 자동 fallback하지 않는다.
2. 임의 생성한 24자 이상 소유자 2차 승인값을 `MONEYGUN_OWNER_API_TOKEN`에 넣는다.
3. 운영 PostgreSQL, HTTPS 주소, OIDC 발급자·클라이언트, 외부 비밀관리, 오류 감시, 관리형 시점복구 값을 연결한다.
4. 새 릴리스 후보 commit을 만들고 `릴리스 점검`이 통과한 뒤에만 `MONEYGUN_RELEASE_APPROVED=true`, 마지막으로 `KIWOOM_TRADING_ENABLED=true`를 설정한다.
5. 위 값 중 하나라도 없으면 내일은 조회·그림자 운용만 한다. 코드는 로컬 환경의 실주문을 의도적으로 거부한다.

## 08:35 시작

프로젝트 폴더에서 다음을 실행한다.

```powershell
.\scripts\start-local.ps1
```

브라우저의 `운영 센터 → 실거래 활성화 센터`에서 `L0 실행 가능`인지 확인한다. `실주문 차단`이면 아래 주문 단계로 넘어가지 않는다.

## 08:40 계좌·안전 확인

`그림자 주문` 화면에서 순서대로 실행한다.

1. `상태 새로고침`: 운영계좌, 주문 잠금 준비됨인지 확인
2. `계좌 동기화`: 실제 평가자산이 파일럿 자본 50,000원 이상인지 확인
3. 후보 종목 6자리 코드를 입력하고 `공식 시세 저장`
4. `계좌 대사`: PASS 확인
5. 소유자 승인 토큰 입력
6. 현재 단계가 R0이면 `5만원 L0 시작 승인`

호가는 주문안 생성 시점 기준 15초, 계좌 대사는 30초를 넘으면 다시 실행해야 한다.

## 주문 가능 창

- 집중투자: 09:05~09:10
- 장초 단타: 첫 10분 관찰 후 09:10~10:30, 11:00 전량청산
- 종가매매: 15:20~15:27

모드가 만든 공식 `KIWOOM_*` 그림자 주문에서 `L0 실주문안 사전점검`을 누른다. 사전점검 통과 후 `5분 승인`, 그다음 붉은 `실주문 제출`을 누를 때만 키움 주문 호출이 발생한다. L0에서는 매 주문을 사용자가 승인한다.

## L0 고정 한도

- 실투입 자본: 50,000원
- 한 주문: 최대 45,000원
- 동시 보유: 1종목
- 하루 신규매수: 최대 3건
- 당일 방어손익: -1,500원 도달 시 신규매수 중지
- 누적손익: -5,000원 도달 시 중지
- 시장가·신용·미수·공매도·파생상품·물타기·자동입금: 금지

이 파일럿은 전략 수익성이 검증되지 않았다. 5만 원 전액 손실 가능성이 있고 수익을 보장하지 않는다.

## 주문 뒤

1. 접수번호가 보이지 않거나 상태가 `UNKNOWN`이면 같은 주문을 다시 누르지 않는다.
2. `계좌 대사`로 미체결·체결을 확인한다.
3. 부분체결 잔량은 자동 재주문하지 않는다.
4. 이상하면 상단 `긴급 중지`를 누른다. 긴급 중지는 무조건 시장가 청산이 아니라 신규 주문 차단이다.
5. 15·30·45·60 실거래일에 `도래한 버전 검토 생성`으로 v1.x/v2 후보를 동결한다. 자동 적용·자동 증액은 없다.

## 절대 금지

- 화면이 `실주문 차단`인데 환경 플래그만 억지로 켜기
- 코드에 조회→주문 키 자동 fallback을 추가하거나 키를 채팅·Git에 노출하기
- `.env`, 키, 계좌번호, 승인 토큰을 채팅이나 Git에 올리기
- `UNKNOWN` 주문 재전송
- 손실 한도·킬 스위치·대사 오류 우회
