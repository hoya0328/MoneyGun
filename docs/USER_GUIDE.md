# Signal Guild 사용자 가이드

최종 갱신: 2026-09-03

이 문서는 Signal Guild를 실제로 켜고, 직원들의 판단을 확인하고, 5만 원 L0 종가매매 후보를 검토해 키움 실주문까지 진행하는 방법을 설명한다. Signal Guild는 수익을 보장하지 않는다. L0는 전략 수익성이 아직 검증되지 않은 실험이며 투입한 5만 원 전액을 잃을 수 있다.

## 1. 현재 사용할 수 있는 범위

| 기능 | 현재 상태 | 사용자 행동 |
|---|---|---|
| 키움 운영계좌 조회 | 사용 가능 | 계좌 동기화·공식 시세·대사 |
| 5만 원 L0 원장 | L0 단계 | 수동 5분 승인 또는 `L0-AUTO-v1` 위임 |
| 종가매매 v3-L0 | 후보 생성 구현 완료 | 15:05 스캔, 15:20 주문안 준비 |
| 종가·멀티모드 자동 준비 | 사용 가능 | 전략 시간대에 후보·주문안 자동 준비 |
| L0 무인 실주문 | 소유자 위임 시 사용 가능 | 활성화 뒤 새 주문안만 자동 승인·제출 |
| 집중투자 v2-L0 | 소액 실험 경로 구현 | 15:35 스캔, 다음 장 09:05 주문안 |
| 장초 단타 v3-L0 | 소액 실험 경로 구현 | 08:50부터 실시간 수집, 09:10 이후 주문안 |
| 안전투자 v1-L0 | 소액 실험 경로 구현 | 15:35 스캔, 다음 장 09:05 주문안 |
| 장기투자 v1-L0 | 기술적 소액 실험 경로 구현 | 재무 OOS 전 확대 운용 금지 |

Signal Guild는 계좌에 원래 있던 종목을 자동 관리하지 않는다. 기존 외부 보유종목은 Signal Guild가 매도하거나 위험 한도에 포함하지 않는다. Signal Guild 실체결 계보로 새로 산 종목만 관리 종목이 된다.

## 2. 가장 짧은 시작 순서

1. Windows PC의 전원과 인터넷 연결을 유지하고 해당 Windows 사용자로 로그인한다.
2. 브라우저에서 `http://127.0.0.1:5173/`을 연다.
3. 상단에 `MISSION HALTED`가 표시되면 신규 주문을 시도하지 않는다.
4. `그림자 주문` 화면에서 소유자 승인 토큰을 입력한다. 토큰은 화면 메모리에만 있고 저장되지 않는다.
5. `운영 센터 → 내 컴퓨터 24시간 운영 → 기동 후 복구 대사`를 누른다.
6. `복구 대사 완료`, `DESKTOP_LIVE_ELIGIBLE`, 계좌 대사 `PASS`를 확인한다.
7. `그림자 주문 → L0 무인 실주문` 상태를 확인한다. 자동화를 원하면 토큰을 입력한 뒤
   `L0 무인 실주문 켜기`를 누른다.
8. 종가매매를 이용할 날에는 15:05 전까지 위 과정이 끝나 있어야 한다.

API나 PC가 재시작될 때마다 `RECOVERY_REQUIRED`로 돌아가는 것이 정상이다. 이전 대사가 PASS였더라도 다시 `기동 후 복구 대사`를 해야 주문 잠금이 열린다.

## 3. 화면별 사용법

### 오늘의 작전실

- 미션 자본, 현재 노출, 이익 금고와 직원 작업 상태를 한눈에 본다.
- 후보와 직원 의견은 참고 정보다. 이 화면에서 브로커 주문은 전송되지 않는다.
- 김안전 또는 김반대가 차단 사유를 표시하면 주문 화면에서 원인을 먼저 확인한다.

### 투자위원회

- 직원별 분석, 찬성·반대 논거, 위험 심사와 최종 결정을 읽는다.
- `HOLD`는 오류가 아니라 조건을 통과한 종목이 없다는 정상 결정일 수 있다.
- 근거가 오래됐거나 데이터가 부족하면 후보 점수가 높아도 거래하지 않는다.

### 직원 사무실·도감

| 직원 | 담당 업무 |
|---|---|
| 김데이터 | 가격·종목 생애주기·시장조치 데이터 확인 |
| 김뉴스 | 공시·뉴스·돌발 악재 근거 정리 |
| 김차트 | 추세·거래량·변동성·가격 위치 분석 |
| 김시장 | 시장 국면과 벤치마크 상태 확인 |
| 김찬성 | 매수 논거와 상승 시나리오 제시 |
| 김반대 | 과열·유동성·악재·실패 시나리오 제시 |
| 김안전 | 수량·계획손실·자본 한도·중지선 계산 |
| 김투자 | 의견을 종합해 BUY 후보 또는 HOLD 결정 |
| 김주문 | 공식 호가·대사·승인·주문 상태 관리 |

직원 설명은 근거를 읽기 쉽게 만드는 역할이다. 주문 수량, 손실 한도와 제출 가능 여부는 직원의 자유 판단이 아니라 결정론적 코드가 계산한다.

#### 김뉴스의 뉴스룸

직원 사무실의 `김뉴스의 뉴스룸`은 말풍선 샘플이 아니라 실제 OpenDART 공식 공시
감시 결과다.

- 평일 07:30~18:30 KST에 5분마다 고정 유니버스·최근 후보·Signal Guild 주문 의도 종목을
  확인한다. 화면은 60초마다 최신 상태를 다시 읽는다.
- `INFO`는 방향을 추측하지 않고 원문 근거만 기록한다.
- `WARNING`은 유상증자·전환사채·감자·정정 같은 확인 필요 사건이며 소유자가
  `확인 완료`를 기록할 때까지 해당 종목 신규 매수를 막는다.
- `CRITICAL`은 횡령·배임·상장폐지·거래정지 같은 중대 사건이며 확인 기록을 남겨도
  발견 후 72시간 신규 매수 차단이 유지된다.
- `지금 공식 공시 확인`은 수집만 실행한다. 주문 승인·제출은 하지 않는다.
- OpenDART 마지막 성공 수집이 없거나 실패했거나 운영 중 15분 넘게 오래되면 모든 신규
  매수가 실패 폐쇄된다. 위험축소 매도와 계좌 대사는 계속 가능하다.

일반 포털 기사와 SNS는 현재 자동 분석하지 않는다. 뉴스룸의 `라이선스 뉴스 공급자 ·
미연결` 표시는 오류가 아니라, 정식 API·이용권한이 없는 기사를 임의 수집하지 않는다는
뜻이다. 각 공시의 `DART 원문 열기`로 공식 원문을 직접 확인할 수 있다.

### 그림자 주문

실사용에서 가장 중요한 화면이다.

- `읽기 전용 연결`: 키움 실전 조회 키 상태, 계좌 동기화와 공식 시세를 확인한다.
- `오늘 종가매매 전시장`: 오늘 스캔 상태, 1주 매수 가능 종목 수, 상세 분석 수와 후보/HOLD 사유를 본다.
- `5만 원 실거래 실험실`: 평가금액, 당일 방어손익, 실거래일과 신규진입 횟수를 본다.
- `Execution Guardian`: L0 단계, 긴급 중지, 주문 환경과 현재 차단 사유를 본다.
- `김주문 작업대`: 그림자 주문과 실주문안 사전점검을 관리한다.
- `실주문 의도 금고`: 수동 5분 승인 또는 위임 자동 승인과 키움 제출 상태를 보는 마지막 구역이다.

`실주문 제출` 버튼은 실제 금융거래를 발생시킬 수 있다. 종목, 수량, 지정가, 무효화 가격과 차단 사유가 없는지 확인한 뒤에만 누른다.

### 운영 센터

- `오늘 업무 실행`: 장 종료 후 일일 연구·대사·기록을 실행한다.
- `실거래 활성화 센터`: L0 주문 가능 여부와 첫 번째 차단 사유를 확인한다.
- `안전 백업 만들기`: 암호화된 SQLite 백업을 만든다.
- `복구 훈련`: 별도 임시 DB에서 백업을 복원해 검증한다.
- `기동 후 복구 대사`: API 재기동 후 미체결·체결·잔고와 내부 원장을 맞추고 `ARMED`로 전환한다.
- `집중/안전/장기 모드 실행`: 15:35 이후 후보를 만들고 다음 장 09:05에 주문안을 준비한다.
- `장초 실시간 단계 실행`: 08:50 감시목록부터 09:00~10:30 실시간 신호 단계를 진행한다.
- `청산 감시 실행`: Signal Guild 관리 체결만 손절·최대 보유기간·수익 추적·11시 청산 조건으로 검사한다.

## 4.1 다른 L0 모드 사용 시간

| 모드 | 후보 준비 | 진입 주문안 | 기본 청산 감시 |
|---|---|---|---|
| 집중투자 | 15:35~18:00 | 다음 거래일 09:05~09:10 | 무효화·14일·+5% 후 2% 추적 |
| 장초 단타 | 08:50 감시, 09:00~09:10 주문금지 관찰 | 09:10~10:30 | 무효화·+1.5% 후 0.8% 추적·11:00 전량 |
| 안전투자 | 15:35~18:00 | 다음 거래일 09:05~09:10 | 무효화·90일·+10% 후 4% 추적 |
| 장기투자 | 15:35~18:00 | 다음 거래일 09:05~09:10 | 무효화·365일 검토·+20% 후 7% 추적 |

운영센터의 모드 버튼은 현재 시간의 한 단계를 실행한다. 시간이 아니면 우회하지 않고
대기/차단 이유를 보여준다. 멀티모드 스케줄러가 켜지면 이 호출을 대신한다.
`L0-AUTO-v1`이 꺼져 있으면 주문 승인과 제출은 사용자가 직접 하고, 켜져 있으면 활성화 뒤
만들어진 새 주문안만 자동 처리된다. 5만 원에서는 어떤 모드를 선택해도
동시에 한 종목만 보유하므로, 열린 포지션이 있으면 다른 모드의 신규 매수는 차단된다.

## 4. 종가매매 하루 사용 순서

### 오전 또는 장 마감 후 — 자격 데이터 자동 갱신

- PC가 켜져 있으면 김데이터가 거래일 18:30 이후 자동 갱신하고, 다음 날 06:00~08:20에
  게시 지연·PC 종료를 보충하기 위해 다시 확인한다.
- `운영 센터 → 실거래 데이터 자격 관문 → 김데이터 일일 자동 갱신`에서 최근 성공 기준일과
  진행 단계를 확인한다. `최신 검증 완료`면 별도 조작이 필요 없다.
- `실패` 또는 `중단`이면 오류를 확인한 뒤 인터넷과 공공데이터 서비스키를 점검하고
  `지금 다시 갱신`을 누를 수 있다. 실패 상태에서는 기존 3일 신선도 제한을 우회하지 않는다.
- 자동 갱신은 데이터만 수집·검증하며 실제 주문을 제출하지 않는다.

### 15:00 이전 — 준비

1. PC 전원, 인터넷, Windows 시각 동기화를 확인한다.
2. Signal Guild를 열고 소유자 토큰을 입력한다.
3. `기동 후 복구 대사`를 실행한다.
4. `긴급 중지 정상`, `운영계좌`, `L0 운용 중`, 차단 사유 없음 또는 허용 가능한 사유인지 확인한다.
5. 기존 외부 보유종목이 `관리 제외`로 표시되는지 확인한다.

### 15:05~15:10 — 전시장 스캔

`그림자 주문 → 오늘 종가매매 전시장 → 현재 단계 실행·새로고침`을 한 번 누른다.

스캔은 다음 순서로 동작한다.

1. 키움 공식 거래대금 순위에서 KOSPI·KOSDAQ 전체와 1만 원 미만 구간을 찾는다.
2. KRX/KIND 자격 데이터로 보통주, 상장 상태, 주의·경고·위험·관리·환기·거래정지를 확인한다.
3. 1주 가격이 2,000~45,000원인 종목을 남긴다.
4. 최대 16종목의 공식 현재가·시가총액·200일 일봉을 상세 분석한다.
5. 통과 종목이 없으면 `조건 미달 · 보류`로 끝낸다.

소형주는 시가총액 500억~1조 원으로 표시한다. 작다는 이유로 점수를 더 주지 않으며 시가총액 500억 미만, 20일 중앙 거래대금 50억 미만 또는 당일 거래대금 30억 미만은 제외한다.

### 15:10~15:19 — 후보 검토

- 종목명·종목코드·점수·수량·후보 이유를 읽는다.
- 김반대와 김안전의 반대 근거를 먼저 확인한다.
- 이해되지 않거나 원치 않는 종목이면 아무 버튼도 누르지 않는다.
- 후보가 없으면 그날 거래는 끝이다. 다른 종목을 억지로 선택하지 않는다.

### 15:20~15:27 — 주문안 준비

후보가 있을 때 `현재 단계 실행·새로고침`을 다시 누른다.

시스템은 최신 15초 호가, 30초 이내 계좌 대사, L0 현금·노출·손실선과 주문 시간을 재검사한다. 통과하면 그림자 주문과 `AWAITING_APPROVAL` 실주문 의도를 만든다. 이 단계까지는 키움에 주문을 제출하지 않는다.

자동 준비 스케줄러는 위 두 시간대 호출을 대신한다. `L0-AUTO-v1`이 켜져 있으면 별도
실행 워커가 새 주문안을 최신 호가·계좌 대사·뉴스·위험 관문으로 다시 검사한 뒤 승인과
지정가 제출을 수행한다.

### 5분 승인과 실제 제출

1. `실주문 의도 금고`에서 상태가 `AWAITING_APPROVAL`인지 확인한다.
2. 종목, 매수/매도, 수량, 지정가와 주문금액을 다시 확인한다.
3. `5분 승인`을 누른다.
4. 상태가 `READY`로 바뀌면 5분 안에 `실주문 제출`을 누른다.
5. `ACKNOWLEDGED`, `PARTIALLY_FILLED`, `FILLED` 중 어느 상태인지 확인한다.

승인 후 가격·수량·범위가 바뀌면 기존 승인을 재사용할 수 없다. 15:27이 지나거나 승인 시간이 끝나면 그날 주문을 포기한다.

### L0-AUTO-v1 무인 실주문

1. `복구 대사 완료`, `L0 운용 중`, 김뉴스 `READY`, 긴급 중지 `정상`을 확인한다.
2. 소유자 토큰을 입력하고 `L0 무인 실주문 켜기`를 누른다.
3. 화면의 `L0 무인 실주문 켜짐`을 확인한다. 켜기 전부터 있던 대기 주문은 자동 제출되지 않는다.
4. 이후 전략 스케줄러가 새 주문안을 만들면 10초 주기의 단일 실행 워커가 공식 호가와
   계좌 대사를 갱신하고, 모든 가디언 검사를 통과한 경우에만 지정가 주문을 제출한다.
5. 주문창이 끝날 때까지 미체결이면 취소를 시도한다. 부분 체결 잔량이나 응답 불명 주문을
   새 주문으로 다시 제출하지 않는다.

자동화를 끄면 새 자동 승인·제출만 멈춘다. 이미 증권사에 접수된 주문은 사라지지 않으므로
키움 앱과 `실주문 의도 금고`에서 미체결·체결 상태를 확인한다. 예상하지 않은 상태라면
상단 `긴급 중지`를 먼저 누른다.

## 7. 긴급 중지와 재개

### 즉시 멈춰야 하는 경우

- 화면과 키움 앱의 보유수량 또는 체결이 다르다.
- `UNKNOWN` 또는 `CANCEL_UNKNOWN`이 표시된다.
- 예상하지 않은 종목·수량·주문이 보인다.
- 인터넷이 반복해서 끊기거나 PC 시각이 틀렸다.
- 손실 한도, 감사, 백업 또는 계좌 대사가 실패한다.

상단 `긴급 중지`를 누르면 신규 주문과 자동화를 막는다. 이미 접수된 주문이나 보유 포지션이 자동으로 사라지는 것은 아니므로 키움 앱에서도 미체결과 보유수량을 확인한다.

프로그램 자체도 끝내야 하면 관리자 권한이 아닌 일반 PowerShell에서 프로젝트 폴더로
이동해 `\.\scripts\Stop-DesktopLive.ps1`을 실행한다. 이 스크립트는 예약 작업을 멈추고
Signal Guild로 검증된 루프백 API·웹만 종료한다. 다시 켤 때는 호환성을 위해 이름을
유지한 Windows 예약 작업 `MoneyGun Desktop Live`를 시작하고 기동 후 복구 대사를 새로 실행한다.

재개할 때는 소유자 토큰을 다시 입력하고 계좌·미체결·체결 대사를 PASS로 만든 뒤 `중지됨 · 재개`를 누른다. 원인을 모르면 재개하지 않는다.

## 8. 장 종료 후 할 일

1. 15:40 이후 `운영 센터 → 오늘 업무 실행`을 누른다.
2. 계좌 대사, 직원 보고와 실제 주문 건수를 확인한다.
3. 체결이 있었다면 수량·가격·수수료·세금과 Signal Guild 원장이 일치하는지 본다.
4. `UNKNOWN`, 대사 차이 또는 감사 오류가 있으면 긴급 중지 상태를 유지한다.
5. 하루 한 번 `안전 백업 만들기`를 실행한다.
6. 적어도 월 1회 `복구 훈련`을 실행한다.

15·30·45거래일에는 v1.x 개선 후보를 검토하고, 60거래일에는 v2 후보를 검토한다. 보고서 생성이 기존 전략을 자동 변경하거나 자본을 늘리지는 않는다.

## 9. 자주 발생하는 문제

### 화면이 열리지 않는다

Windows 예약 작업 `MoneyGun Desktop Live`가 실행 중인지 확인한다. 이 이름은 기존
설치 호환성을 위한 레거시 식별자다. API는 `http://127.0.0.1:8000/health`, 화면은
`http://127.0.0.1:5173/`에서만 접근한다. 공유기 포트를 열거나 외부 주소로 노출하지 않는다.

### 키가 준비됐는데 주문이 차단된다

키가 있다는 것과 지금 주문 가능한 것은 다르다. `Execution Guardian → 현재 주문 차단 사유`와 `운영 센터 → 실거래 활성화 센터`의 첫 번째 미통과 항목을 확인한다. 재기동 직후라면 대부분 `기동 후 복구 대사`가 필요하다.

차단 사유가 `김뉴스 공식 공시 감시`라면 직원 사무실의 뉴스룸에서 최신 수집 상태와
해당 종목의 공시를 확인한다. WARNING은 내용을 이해한 뒤 소유자 토큰으로 확인 기록을
남길 수 있다. CRITICAL은 확인만으로 해제되지 않으며 72시간이 지나기 전에 DB나 시간을
수동 변경해 우회하면 안 된다.

### 종가 후보가 없다

`조건 미달 · 보류`면 정상이다. 거래대금·가격·시가총액·추세·거래량·고가권·시장조치 조건을 동시에 통과한 종목이 없다는 뜻이다. `스캔 시간 놓침` 또는 `오늘 주문창 종료`와 구분한다.

### 승인 버튼이 눌리지 않는다

소유자 토큰이 비어 있거나, 주문안이 `AWAITING_APPROVAL`이 아니거나, 다른 작업이 진행 중일 수 있다. 토큰을 채팅이나 파일에 붙이지 말고 화면 입력란에만 직접 입력한다.

### 주문이 UNKNOWN이다

같은 주문을 다시 제출하지 않는다. 긴급 중지를 유지하고 키움 미체결·체결 조회와 Signal Guild 대사를 수행한다. 확인 전까지 수동으로 같은 주문을 중복 제출하지 않는다.

## 10. 절대 하지 말아야 할 것

- App Key, Secret, 소유자 토큰, 계좌번호와 계좌 비밀번호를 채팅·Git·스크린샷에 노출하지 않는다.
- 차단을 피하려고 PC 시각, DB, 검증 기록 또는 환경 플래그를 임의로 조작하지 않는다.
- `UNKNOWN` 주문을 재전송하지 않는다.
- 후보가 없다는 이유로 시간문을 우회하거나 다른 종목을 수동으로 끼워 넣지 않는다.
- 기존 외부 보유종목을 Signal Guild 관리 종목으로 임의 변경하지 않는다.
- 별도 승인 없이 5만 원 이상으로 자본을 확대하지 않는다.

## 11. 현재 환경에서 바로 해야 하는 일

2026-09-03 기준 L0 단계에서 종가·멀티모드·김뉴스 준비와 `L0-AUTO-v1` 실행 워커를
운영할 수 있다. 실제 활성 상태는 화면의 `ARMED`, 김뉴스 `READY`, `L0 무인 실주문`으로
확인하며 API가 재기동되면 항상 `RECOVERY_REQUIRED`로 돌아간다.

따라서 다음 거래일 전 순서는 아래와 같다.

1. `그림자 주문`에서 소유자 토큰 입력
2. `운영 센터`에서 `기동 후 복구 대사`
3. `DESKTOP_LIVE ARMED`와 차단 사유 없음 확인
4. 직원 사무실 뉴스룸에서 최신 OpenDART 수집과 미확인 공시 확인
5. `L0 무인 실주문 켜짐` 또는 수동 승인 모드인지 확인
6. 전략별 시간대에 후보·주문·차단 결과 확인

무인 실주문을 켜도 5만 원 자본, 기존 보유종목 제외, 뉴스 차단, 손실 중지와 킬 스위치는
계속 적용된다. 이는 전략 수익성이 검증됐거나 L2로 승격됐다는 뜻이 아니다.
